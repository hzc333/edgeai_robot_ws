# ADR-0001：首版Task 1采用单主机器人建图

状态：已采用  
适用版本：比赛系统v0.1～首个端到端里程碑

## 背景

规则允许Task 1使用一台或两台机器人，但不强制双机器人建图。当前仓库只有单机器人SLAM基线，双机器人地图对齐、共享定位和回环融合会显著增加首个里程碑风险。

## 决策

- `robot_1`作为首版Task 1主机器人，负责SLAM、自主探索、相机观测和地图保存。
- `robot_2`必须能够同时连接、发布状态并接受安全/阶段命令，但首版不向权威地图写入扫描或轨迹。
- `robot_2`可以用于接口连通性、状态汇总、定位实验和Task 2准备；未经后续ADR批准，不参与首版权威建图。
- Task 1最终只有一个`map_id`和一个地图发布源。
- 达成端到端里程碑后，再基于测量结果决定是否启用双机器人协同探索或地图融合。

## 原因

- 最短路径满足比赛里程碑和规则。
- 避免多个`map -> odom`发布源冲突。
- 优先验证探索、ArUco、保存地图、重新定位和普通救援完整链路。
- 第二台机器人仍提前验证命名空间、状态汇总和安全接口。

## 后续升级条件

只有满足以下条件，才评估双机器人Task 1：

1. 单机器人连续三次完成自主探索和有效地图导出。
2. 两台机器人命名空间、TF和时间同步稳定。
3. 存在可量化的时间或覆盖率收益目标。
4. 已确定共享定位/地图融合算法和失败回退方案。
5. 新方案不会降低Task 1目标定位精度和Task 2地图可用性。
